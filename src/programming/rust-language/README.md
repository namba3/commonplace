# Rustは何を再設計したのか――Cの構文、MLの思想、所有権で結ばれた言語機能

作成日：2026-10-15 / 更新日：2026-10-15

> **概要：** Rustは単に「GCを必須としないメモリ安全なシステムプログラミング言語」ではない。C/C++に近い実行制御の上に、ML/OCamlの代数的データ型・パターンマッチ・式志向、Haskellの型クラスを連想させるTraitと関連型、そして所有権・借用によるアクセス制約が組み合わされている。こうした機能がなぜ1つの言語として噛み合うのかを、コード例とコンパイラの仕組みから考察する。

> **対象読者：** C/C++、C#、Python、TypeScriptなどの経験があり、Rustの全体像や設計上の特徴を理解したい人。Rustの入門チュートリアルではなく、複数の言語パラダイムを横断する解説・考察である。
>
> **対象時点と検証範囲：** 2026年10月15日時点の公式資料を参照している。コードには独立した例と、前後の定義を必要とする断片が混在するため、網羅的なコンパイル検証は行っていない。「美しい」「Cの正統な後継」は仕様上の保証ではなく筆者の評価である。

**読み方：** 全体像をつかむには第1部から順に読む。言語機能の由来と組み合わせを知りたい場合は第1〜4部、低水準制御やコンパイラ、利用領域に関心がある場合は第5部、Cの後継候補としての評価や課題・展望を知りたい場合は第6部から読むとよい。各部の内容は下記のシリーズ構成を参照。
