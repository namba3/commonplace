# 第4回：Adaptive Depth・KVキャッシュ・固定点――反復をどう効率化するか
作成日：2026-11-03 / 更新日：2026-11-03

> **この回の問い：** 重みを共有すればパラメータは減る。しかし追加反復を実行する計算コストやKVキャッシュは残る。反復回数の適応、学習時の安定化、固定点の利用によって、実効的な効率はどこまで改善できるのか。

本回は[第3回のDepth ConditioningとHistory-State Injection](03-depth-conditioning-and-history.md)を踏まえ、**反復を制御すること**から**反復を効率よく実行・省略すること**へ視点を移す。両者は関連するが、同じ目的関数ではない。

## 1. パラメータ効率、計算量、学習の難しさ

共有Coreが\\(P_C\\)個のパラメータを持ち、PreludeとCodaが\\(P_P,P_D\\)個のパラメータを持つなら、概略の重み数は

\\[
P_{\mathrm{total}}\approx P_P+P_C+P_D
\\]

であり、反復回数\\(R\\)にほぼ依存しない。一方、Coreの1回分の計算を\\(C_C\\)とすれば、**入力長・計算グラフ・キャッシュ方針を固定した**近似として

\\[
C_{\mathrm{forward}}\approx C_P+R\,C_C+C_D
\\]

である。

つまり、**パラメータ効率と計算効率は別問題**だ。さらに、推論時の「同じFLOPs」でも、長い文脈を扱うAttentionと小さいCoreの行列演算とではメモリアクセスやGPU利用率が異なる。同一FLOPsでの優劣は、同一レイテンシでの優劣を保証しない。

| 指標 | Coreの反復を増やした場合 |
| --- | --- |
| 保持する共有重み | 原則増えない |
| 実行する演算 | 一般に増える |
| 逐次依存によるレイテンシ | 増えやすい |
| KVキャッシュ | 何をいつ保存・再計算するかによって異なる |
| 推論性能 | 課題、学習方式、反復数によって変わり、単調改善は保証されない |
| 重みの転送負荷 | 共有重みを再利用できれば削減できる場合があるが、実装依存 |

### 1.1 Adaptive Depth：追加計算をどこに配るか

容易な入力と難しい入力に同じ計算を割り当てるのは非効率かもしれない。そこで、生成位置\\(t\\)の反復回数を

\\[
R_t = g(c_t, b)
\\]

のように決める構想がある。\\(c_t\\)はその生成位置で利用可能な文脈、\\(b\\)は計算予算である。

停止機構には、学習されたHalting Gate、出力分布の変化、状態更新の収束、固定の上限などが考えられる。だが、状態の変化が小さいことは、回答の正しさを意味しない。反復を増やし過ぎて答えが悪化する可能性もある。

### 1.2 学習時の反復と勾配

同じCoreを何十回も繰り返せば、学習時の計算グラフは深くなり、逆伝播のメモリや安定性に課題が生じる。反復回数を変えて学習する、勾配を伝える区間を制限する（Truncated Backpropagation Through Timeに相当）、更新量や正規化の挙動を調節する、といった設計が必要になる。勾配を切り詰めれば学習時のメモリを抑えやすいが、長い反復をまたぐ依存関係の最適化には制約が生じ得る。

加えて、同じ重みが繰り返し訪問されることで、**勾配や残差スケーリングの条件が独立層の場合と異なる**。2026年の[DeepLoop: Depth Scaling for Looped Transformers](https://arxiv.org/abs/2607.13491)は、この重みの反復訪問に着目した安定化規則を分析した。ただし、報告された利点は主にGPT-2規模の実験に基づき、フロンティアモデルまで自動的に一般化できない。

ここでも重要なのは、「重みを何回も呼び出せる」ことと「任意の回数で安定して学習・推論できる」ことの間には距離がある、という点だ。

### 1.3 反復の安定性：同じ重みを使うほど小さな更新が安全とは限らない

状態更新を \\(h_{r+1}=F_\theta(h_r)\\) とすると、状態の微小なずれが次の反復へどのように伝わるかは、各段階のJacobian \\(J_r=\partial F_\theta/\partial h|_{h_r}\\) に依存する。

\\[
\delta h_R\approx J_{R-1}J_{R-2}\cdots J_0\,\delta h_0
\\]

したがって、重みの数が一定でも、反復回数を増やせば**誤差・勾配・状態の不安定性が蓄積する場合**がある。単一のJacobianの固有値だけでなく、**反復に沿ったJacobianの積**を見る必要がある。非正規行列では固有値の絶対値が小さくても過渡的な増幅が生じ得るし、反復点ごとにJacobianが異なれば、単純なスペクトル半径の比較だけでは不十分である。逆に縮小方向の更新では、途中状態が固定点へ向かう可能性もある。ただし、Jacobianの積が小さいことや状態差分が収束することは、タスクの正解への到達を保証しない。

ここで、深度条件付けや履歴注入を加えた更新は単純な固定写像ではなくなる。したがって、学習時の安定性、反復外挿の安定性、出力の正確性はそれぞれ測定すべき対象である。DeepLoopが扱う残差スケーリングの問題と、固定点を利用して計算を省く問題は、こうした関係に位置づけられる。

### 1.4 KVキャッシュの扱い

重みを共有しても、反復ごとのKey/Valueは隠れ状態に依存するため、必ずしも同じではない。すべての反復のKVを保持する設計では、キャッシュ量が増える場合がある。最終反復のみの保存、圧縮、再計算などは候補になるが、精度・メモリ・演算量のトレードオフを生む。

実用性を評価する際には、モデルのファイルサイズだけでなく、**実行時のKV容量、スループット、単一リクエストのレイテンシ、消費電力**まで確認すべきである。

2026年10月の[Hybrid Latent Attention for Looped Language Models](https://arxiv.org/abs/2610.07940)は、この難しさを具体的に扱っている。Ouroの4反復モデルを対象に、最近のトークンのKey/Valueを厳密に保持し、古いトークンを圧縮された潜在表現として持つ方式を提案した。論文の実験では、**トークン当たりのキャッシュ量を10.7分の1**とし、対象条件で**デコードスループットを最大7.4倍**改善したと報告する。ただし、追加の学習・注意機構と評価条件に依存し、Recurrent-Depth一般の速度向上率ではない。特にキャッシュを反復深度ごとに別々に持つ単純実装と、保持対象を制限する実装とでは、同じ重み共有アーキテクチャでもメモリ特性が変わり得る。

## 2. 固定点は「無駄な反復」だけでなく、計算を省く手掛かりにもなる

固定点への接近は、反復の有用性を疑う理由であると同時に、**途中の軌跡を省略・近似できる可能性**も示す。2026年10月の[Towards Looped Models Done Right, Part II: Rethinking at Fixed Points](https://arxiv.org/abs/2610.06833)は、この点から学習・Prefill・KVキャッシュ・強化学習のコストを分析した。

同論文では、反復状態が固定点に近づく性質を利用した、**Truncated Backpropagation**、最終反復のKV共有、Prefillの蒸留、高価な軌跡再実行を避けるRL更新などが研究されている。報告値として、蒸留によるPrefillの最大**1.79倍**の高速化、RL更新の**2倍**の高速化がある。また、1.6B規模で、学習した深度分布と**約3分の1のKVキャッシュ**を用い、固定深度・フルキャッシュ学習に近い下流平均性能を得た。いずれも**論文の条件に限られる結果**である。

固定点利用の効果を考えるときは、**モデルの終端出力が似ていること**と、**途中反復のKey/Valueを省略しても、その後の生成分布や品質が保たれること**を分けたい。さらに、固定点へ近づく速さと、正答に必要な情報を保持する度合いは別に評価する必要がある。ある入力で状態が収束しても、長い文脈・異なるトークン位置・異なる深さ条件で同様に振る舞うとは限らない。

同時に、この研究は「固定点へ早く近づけば常によい」と結論していない。固定深度学習と反復回数に分布を持たせる学習では、途中状態の品質や最終反復KVの再利用可能性が異なる。論文は予測結果から深度分布を学習する方法や、入力方向の成分を除去する *orthogonal injection* を提案している。

ここで、本文の中心仮説に対する**重要な緊張関係**が生じる。

- 固定点へ近づく状態更新は、実験条件によっては途中計算の近似・省略に役立ち得る。
- 一方、明示的な深度条件付け\\(F_\theta(h_r;\tau_r,\Delta\tau)\\)は**反復ごとに更新規則を変える**ため、固定の写像\\(F_\theta\\)の固定点という単純な説明はそのまま適用できない。
- History-State Injectionは現在状態だけでなく過去状態も参照するので、状態を\\(h_r\\)だけで記述する一次の自律系とも異なる。必要なら履歴を含む拡張状態を定義する。

つまり、**収束性・計算の機能分化・可変予算への頑健性は、同じ方向に改善するとは限らない**。固定写像に対する \\(F_\theta(h^*;c)=h^*\\) を論じる場合と、深度により \\(F_\theta(h;\tau_r,c)\\) 自体が変化する場合を区別したい。後者に単一の固定点が存在する保証はない。History-State Injectionでも、厳密には履歴を含む拡張状態の更新則を考える必要がある。**状態の収束が正解を意味するわけではない**ため、反復の早期終了は精度・較正・レイテンシを別々に評価する。

---

**この回の結論：** 重みを共有しても、学習・デコード・KVキャッシュの費用は消えない。収束性と性能の関係を検証したうえで、反復をいつ実行・省略するか設計する必要がある。
